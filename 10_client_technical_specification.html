Le Bouclier Statique — Le Secret de l'Architecture

✅ Notre Architecture
  • 1M visiteurs lisent rankings.json depuis Cloudflare CDN
  • 0 requête à la base de données
  • $0 de coût supplémentaire
  • Cloudflare absorbe le trafic gratuitement et sans limite
  • CRON toutes les 5 min : BDD → Agrégation → JSON → CDN
❌ Architecture Classique
  • 1M visiteurs = 1M requêtes à la BDD
  • Risque d'effondrement sous la charge
  • ~$300 juste pour les lectures
  • Besoin d'un serveur surdimensionné
  • Latence élevée pour chaque visiteur

Intégrations

Intégrations Tierces

Le système s'interface avec 5 services externes. Chaque intégration est documentée avec son rôle, son coût, et les données échangées.

🛡️ 1. Cloudflare Turnstile (Anti-Bot Applicatif)

Objectif : Remplacer Google reCAPTCHA pour protéger le système de vote public contre le spam automatisé et les attaques DDoS de niveau applicatif, sans frustrer l'utilisateur légitime avec des grilles d'images à résoudre.

Vérifiabilité & Conformité :
Turnstile est nativement conforme au RGPD. Contrairement à reCAPTCHA, il ne dépose pas de cookies de tracking inter-sites. De plus, le service est garanti 100% gratuit sans limite de volume par Cloudflare.

Flux Technique & API

  • Le widget client génère un token cryptographique temporaire nommé cf-turnstile-response.
  • Le backend (Edge Function Supabase) intercepte la soumission du vote et bloque l'insertion en base de données.
  • L'Edge Function vérifie la validité du token via une requête POST vers https://challenges.cloudflare.com/turnstile/v0/siteverify en utilisant la clé secrète serveur (stockée dans le Vault Supabase).
  • L'opération d'écriture n'est autorisée que si le score de confiance renvoyé est validé.

📧 2. Resend → bascule vers AWS SES (Emails Transactionnels)

Objectif : Garantir la livraison instantanée (< 2 secondes) des codes OTP à 6 chiffres pour le grand public, et des Magic Links pour l'authentification des journalistes et légendes.

Vérifiabilité des Coûts (Important) :
Le tier gratuit de Resend bloque à 100 emails/jour (3000/mois). Pour encaisser 1 million de votes en 15 jours, l'architecture est conçue pour utiliser le protocole SMTP natif connecté à AWS SES (Simple Email Service). Le coût officiel d'AWS SES est d'exactement 0.10$ pour 1000 emails. Le budget pour 1 000 000 d'OTP est donc de 100$ maximum.

Flux Technique & API

  • Utilisation de l'API REST via POST https://api.resend.com/emails (pour le MVP).
  • Authentification via Bearer Token.
  • Le système est configuré directement dans l'interface de Supabase Auth (Custom SMTP), ce qui permet de passer de Resend à AWS SES en production en changeant simplement une variable d'environnement, sans récrire une seule ligne de code métier.

🌐 3. Webflow CMS API v2 (Synchronisation Headless)

Objectif : Conserver une séparation stricte entre le front-end (Webflow) et la base de données sécurisée (Supabase), tout en gardant les deux systèmes synchronisés automatiquement.

Avantage Client :
Cette intégration permet aux administrateurs de l'événement de modifier les biographies, les photos et les catégories depuis Webflow (très facile d'utilisation), sans jamais risquer de casser la base de données relationnelle complexe des votes.

Flux Technique & API

  • Lorsqu'un profil de nominé est mis à jour dans Supabase, un Database Trigger (déclencheur SQL) est exécuté.
  • Ce trigger invoque une fonction asynchrone qui appelle l'endpoint POST /collections/{collection_id}/items de la nouvelle API v2 de Webflow.
  • Le site Webflow est mis à jour en temps réel via son CMS, qui regénère les pages statiques via Cloudflare en arrière-plan.
  • Diffusion des classements (Haute Charge) : Pour afficher le classement en temps réel sans faire exploser l'API du CMS ni la base de données, Supabase génère automatiquement un fichier statique ranking.json (toutes les X secondes) poussé sur le CDN Cloudflare/AWS. Le front-end (Webflow ou WordPress) vient lire ce fichier léger en JavaScript natif, permettant d'encaisser des millions de visiteurs simultanés.
🔄 Alternative : Compatibilité WordPress

Si la décision technique finale s'oriente vers WordPress au lieu de Webflow, l'architecture Headless de Supabase reste 100% compatible. Le Database Trigger pointera simplement vers l'API REST native de WordPress (/wp-json/wp/v2/nomines) en s'authentifiant avec un Application Password. Cela permet de bénéficier de l'écosystème CMS de WordPress, tout en conservant Supabase comme forteresse sécurisée ultra-rapide pour traiter les millions de votes.

📰 4. Brevo → bascule vers Sendy (CRM Marketing)

Objectif : Gérer la liste d'attente ("Notify Me"), annoncer l'ouverture des votes et promouvoir les résultats finaux, tout en isolant complètement ce flux du moteur d'OTP pour protéger la réputation IP du domaine de vote.

Vérifiabilité des Coûts (Important) :
Mailchimp ou Brevo (en payant) coûtent extrêmement cher pour 100 000+ contacts (plusieurs centaines de dollars par mois). La solution d'architecture propose le duo Sendy + AWS SES. Sendy s'auto-héberge sur une petite instance EC2 ($5/mois) et utilise SES, faisant chuter le coût de la newsletter à environ 1$ pour 10 000 envois.

Flux Technique & API

  • Pendant le MVP : Le formulaire de capture Webflow est directement connecté au endpoint POST /v3/contacts de Brevo via une Webhook native. Brevo permet le stockage gratuit illimité de contacts.
  • Lors du passage à l'échelle (Phase 2) : L'API Sendy (script PHP REST) prend le relais pour l'envoi massif sans surcoût de licence mensuelle.

🏆 5. Padel Data Provider (Alimentation Télémétrie)

Objectif : Alimenter de manière autonome la table TELEMETRIE_CLASSEMENT du système avec les classements officiels FIP / Premier Padel des joueurs nominés.

Performance :
Ce processus s'exécute en tâche de fond (background worker), il n'y a donc aucun impact sur le temps de chargement des pages pour les visiteurs (latence perçue = 0).

Flux Technique & API

  • Configuration de l'extension native PostgreSQL pg_cron dans Supabase.
  • Un worker est planifié pour s'exécuter tous les lundis à 02:00 AM UTC (heure de mise à jour standard des classements ATP/FIP).
  • Le worker fait une requête GET authentifiée vers l'API externe, parse le JSON reçu, et exécute une opération UPSERT de type bulk dans la base PostgreSQL pour mettre à jour l'évolution des joueurs nominés.
Sécurité

Protocoles de Sécurité

Chaque couche de l'architecture est sécurisée indépendamment. La fraude est rendue mathématiquement coûteuse sans jamais dégrader l'expérience du votant légitime.

Authentification par Type de Votant

CollègeMéthodeDurée de sessionSécurité

Légendes (30%) Magic Link envoyé par admin 48h (ou fin du vote) Liste fermée (~18 personnes)

Rate Limiting Anti-Fraude

RègleLimiteAction si dépassée
OTP demandés par IP / heure Max 5 Réponse 200 silencieuse (pas d'email envoyé)
OTP demandés par email / 24h Max 3 Idem — réponse identique au succès
Tentatives OTP incorrectes Max 3 OTP invalidé, blocage 15 minutes
Votes par email_hash / catégorie Max 1 UPSERT — le nouveau vote remplace l'ancien
💡
Pourquoi répondre 200 même en cas de blocage ? Si on répond 429, un bot peut tester des milliers d'emails et savoir lesquels ont déjà voté (énumération). En répondant toujours 200, le bot ne sait jamais s'il a réussi.

Couches de Sécurité en Profondeur

🔒 Row Level Security (RLS)
Chaque ligne de la BDD a sa propre "serrure". Même si quelqu'un pirate la connexion, il ne peut lire que les données autorisées. Les audit logs sont en lecture seule pour tout le monde.
🔑 JWT Signé (HMAC-SHA256)
Chaque session est un badge électronique signé cryptographiquement. Impossible de le falsifier ou de modifier le contenu (voter_type, voter_id) sans invalider la signature.
🧊 OTP Hashé (SHA-256)
Le code OTP n'est jamais stocké en clair en base. Seul le hash SHA-256 est conservé. Même en cas de fuite de la BDD, les codes sont inutilisables.
📋 Audit Trail Immuable
Chaque action admin est enregistrée dans un journal qu'on ne peut ni modifier ni supprimer (REVOKE UPDATE, DELETE). Preuve légale pour le commissaire de justice.

Conformité RGPD

  • Consentement explicite — Checkbox obligatoire avant la saisie d'email
  • Anonymisation — Les votes publics stockent un hash SHA-256 de l'email, pas l'email brut
  • Purge automatique — Les cartes de presse sont supprimées 30 jours après clôture
  • Hébergement EU — Supabase en région eu-west-1, Brevo en Europe
  • Droit à l'effacement — Procédure documentée pour supprimer les données sur demande
